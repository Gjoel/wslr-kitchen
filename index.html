Kitchen and admin modes

Every device opens in kitchen mode: tick off arrivals, mark items used or binned, allocate to functions, and fix use by dates and storage. Everything else lives in admin mode, behind the Admin button in the header.

The admin PIN is set in the ADMIN_PIN constant at the top of the script in this file — open the file in a text editor to change it. A device that has unlocked admin stays in admin until you tap Exit admin.

About

WSLR Kitchen v2.3 (Functions now build themselves from the confirmations sheet). One file, two modes: a simple kitchen mode for the iPad (arrivals tick-off, used, bin, allocate) and a full admin mode behind a PIN (orders, deliveries, functions with a food check against heads, settings). Every group on the confirmations sheet with Catering set to Yes appears under Functions on its own, refreshed each time the page loads. Functions you add in the app sit alongside them in a paler dashed card so the two are easy to tell apart. The link is the Apps Script web app in kitchen-confirmations-feed.gs; paste its URL under Settings, Confirmations sheet.

If you see a "relation does not exist" or "column does not exist" error, run wslr-kitchen-v2-schema.sql and then wslr-kitchen-v2.3-sheet-sync.sql in the Supabase SQL editor.
